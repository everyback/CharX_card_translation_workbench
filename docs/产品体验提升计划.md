# CardLoom Translate 产品体验提升计划

## 1. 计划目的

CardLoom Translate 的核心能力面向 RisuAI CHARX/RISUM 卡片的深度翻译、安全保护和人工审核。当前需要补强的是第一次使用时的产品路径：用户应该能够快速理解卡片被识别出了什么、选择合适的翻译范围，并开始一个可控的翻译任务。

本计划参考轻量工具 CardLingo 的直接编辑体验，但不改变 CardLoom Translate 的专业定位。CardLingo 的公开仓库与实现见：[G2Flava/cardlingo](https://github.com/G2Flava/cardlingo)。

## 2. 产品判断

### 2.1 定位

CardLoom Translate 不是单纯的网页字段编辑器，而是：

> 面向 RisuAI 卡片的安全翻译、审核和导出工作台。

CardLingo 值得借鉴的是上手速度、字段操作和即时反馈；CardLoom Translate 必须保留的差异化能力是：

- CHARX、RISUM 的深度处理。
- 世界书、Lua、正则、协议和资源的结构保护。
- 持久化任务、批次、并发、失败重试和日志。
- 机器译文草稿与人工审核分离。
- 原始触发词保留，目标语言世界书别名只追加。
- API Key 只由后端使用，模型设置保存到 SQLite。

### 2.2 体验目标

- 已配置模型：从打开页面到创建首个翻译任务，目标不超过 4 次主要操作。
- 未配置模型：只填写 API 地址、模型、API Key 和目标语言即可开始。
- 导入后自动告诉用户卡片格式、段落数量、世界书、脚本、协议和资源情况。
- 普通用户不需要先理解所有侧栏页面；高级用户仍然可以进入完整工作台。
- 快捷流程不能跳过扫描、保护、审核和导出前检查。

## 3. 范围与非目标

### 3.1 本计划范围

- 快速开始首页。
- 导入后的自动扫描摘要。
- 翻译范围预设。
- 导入、翻译、审核、导出的向导式主路径。
- 单段落快捷操作、失败重试和审核加速。
- 首次使用、空状态、加载状态和错误提示优化。
- Windows 安装包和便携版交付。

### 3.2 本计划不做的事情

- 不把模型 API 地址、模型、API Key、语言、并发或批次参数重新放回环境变量。
- 不绕过机器译文草稿和人工审核，快捷模式也不能直接覆盖原卡。
- 不默认翻译变量名、ID、路径、URL、正则、Lua 结构、协议壳或按钮触发器。
- 不为了模仿轻量工具而放弃 CHARX/RISUM 的结构保护。
- 不在本阶段重写解析器、调度器或导出器。
- 不新增登录、公网监听或复杂账号体系。

## 4. 分阶段实施

## 阶段一：快速开始与导入摘要（P0）

### 用户流程

```text
打开页面 → 拖入卡片 → 自动扫描 → 查看摘要 → 选择预设
```

### 功能

1. 空项目首页改为快速开始页。
   - 主操作：拖入文件。
   - 次操作：选择文件。
   - 显示支持的 JSON、PNG、CHARX、RISUM 格式。
2. 导入后自动触发现有扫描流程。
3. 在摘要区域显示：
   - 检测到的格式。
   - 角色字段数量。
   - 世界书数量和条目数量。
   - 脚本、Lua、正则和协议引用数量。
   - 可见资源和资源 JSON 数量。
   - 当前可翻译段落数量。
4. 模型未配置时打开精简设置引导。
   - API Base URL。
   - 模型名称。
   - API Key。
   - 源语言、目标语言。
   - 并发和批次进入“高级设置”。
5. 模型已配置时不重复弹出设置窗口，只显示配置状态。

### 实现边界

- 复用现有 `/api/projects/import`、项目概要和扫描接口。
- 不新增配置来源。
- 不改变导入后原始卡片保存方式。

### 验收标准

- 导入一张 CHARX 后，页面能在同一主视图中看到格式和内容摘要。
- 不配置模型时，用户能明确知道缺少什么配置。
- 不支持的文件会在导入前后给出具体提示。
- 导入失败不会创建半成品项目。

## 阶段二：翻译范围预设（P0）

预设只映射到现有扫描范围和保护策略，不创建另一套翻译逻辑。

### 预设一：快速翻译

适合普通角色卡和首次试用：

- 角色名称、标签、描述、性格、场景。
- 首条消息和备选开场。
- 不默认处理世界书、Lua、协议、脚本和资源 JSON。

### 预设二：RisuAI 完整翻译

适合目标为 RisuAI 的复杂 CHARX/RISUM：

- 角色字段。
- 世界书正文、名称、注释和目标语言别名候选。
- 可见脚本 UI。
- 解析出的可见 Lua 文本。
- 可见资源 JSON。
- 协议和高风险字段继续进入保护和人工审核。

### 预设三：仅扫描审核

适合第一次处理陌生卡片：

- 只导入、扫描、保护和标记风险。
- 不调用模型。
- 直接进入段落、协议、引用和资源检查。

### 预设交互

- 每个预设显示“适合谁”和“包含什么”。
- 显示预计段落数和风险范围。
- 默认推荐“快速翻译”，检测到 RISUM 或嵌入模块时推荐“RisuAI 完整翻译”。
- 预设选择后仍允许展开高级范围进行调整。

### 验收标准

- 三个预设都能创建正确的扫描范围。
- 快速翻译不会误把受保护协议和脚本结构加入普通文本翻译。
- 完整翻译能覆盖现有扫描器声明的世界书、脚本和资源可见文本。
- 仅扫描审核不发起模型请求。

## 阶段三：向导式主流程（P1）

在顶部增加轻量流程指示：

```text
导入 → 扫描 → 翻译 → 审核 → 导出
```

### 行为

- 导入完成后自动显示扫描摘要。
- 扫描完成后突出“选择翻译预设”。
- 创建任务后自动进入 Jobs，并显示任务进度和失败数。
- 任务完成后自动进入 Review，并默认筛选待审核和有风险项目。
- 审核完成后突出“生成审核草稿”和“导出”。
- 每一步只有一个主要按钮，侧栏仍可用于高级导航。

### 状态要求

- 导入中、扫描中、翻译中、审核中和导出中都显示明确状态。
- 页面刷新后根据 SQLite 中的项目和任务状态恢复当前步骤。
- 任务失败时保留当前项目和已完成译文，只提供“重试失败项”“重新翻译”和“返回审核”等相关操作。

## 阶段四：即时操作与审核加速（P1）

### 段落级操作

在段落或审核条目旁提供：

- 翻译此段。
- 查看原文。
- 回退到翻译前。
- 重试此段。
- 标记为不翻译。

### 审核页加速

- 默认优先显示高风险、失败、保护符号异常和语言行为异常项目。
- 增加“批准安全项”按钮。
- 增加“批准并打开下一项”操作。
- 支持按世界书、脚本、协议、资源和普通文本筛选。
- 允许批量载入机器译文，但不等于批量批准导出。

### 任务页加速

- 失败项直接显示失败原因和重试按钮。
- 显示当前批次、完成数、失败数和剩余数。
- 允许暂停、继续、取消和仅重试失败项。

## 阶段五：细节打磨与验证（P2）

### 体验细节

- 记住最近一次使用的目标语言和预设，但保存到现有 SQLite 设置或项目状态，不使用环境变量。
- 为没有世界书、没有脚本、没有资源的卡片提供简洁空状态。
- 将高级配置折叠，避免首次使用看到过多并发、批次和图片模型参数。
- 为关键图标按钮补充 tooltip 和无障碍标签。
- 保持桌面端密集布局，同时检查窄屏下按钮、文本和状态不重叠。
- 为快捷键提供可选支持：开始任务、打开审核、跳过当前项和导出。

### 验证范围

- JSON、PNG、CHARX、RISUM 导入和导出。
- 普通角色卡、含世界书卡片、含 RISUM 模块的 CHARX。
- 包含 Lua、正则、协议、按钮触发器和资源引用的复杂卡片。
- 无模型配置、模型请求失败、部分批次失败、刷新页面和重新打开项目。
- API Key 不出现在前端响应、日志、构建产物和错误提示中。

## 5. 技术落点

### 前端

- `src/app/WorkbenchApp.tsx`：快速开始、主流程状态和页面跳转。
- `src/app/hooks/import/useCardImport.ts`：导入完成后的自动摘要和流程入口。
- `src/app/hooks/projects/useProjectActions.ts`：扫描与预设映射。
- `src/app/hooks/translation/useTranslationTasks.ts`：预设创建任务、完成后的审核跳转。
- `src/features/card-inspection/ProjectOverviewView.tsx`：摘要卡片和推荐预设。
- `src/features/segments/SegmentsView.tsx`：段落级快捷操作。
- `src/features/jobs/JobsView.tsx`：任务进度、失败重试和向导下一步。
- `src/features/review/ReviewView.tsx`：风险优先、批准和下一项操作。
- `src/features/settings/SettingsDialog.tsx`：精简设置与高级设置折叠。

### 后端与持久化

- 优先复用现有项目、扫描、任务、审核和导出接口。
- 如果需要保存最近预设，优先使用现有 SQLite 设置机制或项目字段。
- 不把翻译控制参数写回 `.env`。
- 不在路由中新增大型解析、事务或调度逻辑。
- 新增工作流编排时放入对应的 `server/application/` 服务。

## 6. 测试计划

### 单元与集成测试

- 预设到扫描范围的映射测试。
- 快速翻译不包含高风险字段的测试。
- 完整翻译覆盖世界书、脚本 UI、可见 Lua 和资源 JSON 的测试。
- 仅扫描审核不创建模型任务的测试。
- 导入失败回滚和任务创建失败回滚测试。
- 任务完成、部分失败、暂停、继续和重试失败项测试。
- 页面刷新后根据 SQLite 状态恢复步骤的测试。

### 手工验收卡

至少准备以下卡片：

1. 普通 PNG 角色卡。
2. 普通 JSON 角色卡。
3. 含世界书的 CHARX。
4. 含 RISUM 模块的 CHARX。
5. 含 Lua、正则、协议和资源引用的复杂 RisuAI 卡片。

每张卡都要在目标客户端重新打开导出结果，检查角色正文、世界书触发词、脚本、协议和资源引用。

## 阶段六：Windows EXE 交付（P1/P2）

### 目标

提供不要求用户安装 Node.js、Docker 或手动启动命令的 Windows 使用方式，同时保留 Docker 作为服务器和高级用户部署方式。

### 推荐形态

第一版优先提供两种产物：

1. **Windows 安装包**：安装后创建开始菜单和桌面入口，适合普通用户。
2. **Windows 便携版**：解压后运行，不写入安装目录中的用户数据，适合测试和绿色部署。

应用启动后在本机启动 Fastify 服务，并用内置窗口打开工作台。服务仍只绑定 `127.0.0.1`。安装版的模型设置、API Key、项目和 SQLite 数据写入 Windows 用户数据目录，而不是安装目录或程序包内部；便携版为了支持拷贝目录即迁移，把这些数据放在 EXE 同目录的 `data/` 中。

### 技术方案

- 使用 Electron 作为桌面壳，复用现有 React/Vite 前端和 Node/Fastify 后端。
- Electron 主进程负责启动和关闭本地 Fastify 服务、等待健康检查、创建窗口和处理退出清理。
- Renderer 开启 `contextIsolation`，关闭 Node 集成，不让前端页面直接访问文件系统或 API Key。
- 为桌面模式增加可配置的用户数据根目录，默认使用 Electron 的 `userData` 路径。
- 启动时优先选择空闲的本机端口，避免与 8787 或其他本地服务冲突；窗口只加载本地服务地址。
- 使用安装包工具生成安装版和便携版，并在发布前配置 Windows 代码签名。

### 不采用的第一版方案

- 不立即把整个应用压成单个自解压 EXE。
- 不用 Node.js SEA 作为第一版打包路径。当前项目是 Node 22、TypeScript ESM，并依赖 `node:sqlite`；SEA 目前仍处于 active development，打包和原生运行时兼容性需要单独验证。
- 不把 SQLite 写入 `Program Files`、安装包资源目录或项目源码目录。
- 不因为桌面模式而允许公网监听。

### 桌面版验收标准

- 全新 Windows 机器无需预装 Node.js 或 Docker 即可启动。
- 安装版和便携版都能导入 JSON、PNG、CHARX、RISUM。
- 关闭并重新打开程序后，项目、模型设置和审核状态仍然存在。
- 升级程序版本不会覆盖用户数据；卸载时明确区分程序文件和用户数据。
- API Key 不进入 renderer、日志、安装包构建产物或错误弹窗。
- 8787 被占用时仍能启动，退出后不会留下孤立的 Fastify/Node 进程。
- 桌面版与 Docker 版共用同一套解析、扫描、调度、审核和导出测试。

### 发布顺序

```text
先完成快速开始体验
→ 抽离可复用的 server create/start/stop 生命周期
→ 加入 Electron 开发壳
→ 构建 Windows 便携版
→ 构建 Windows 安装包
→ 签名、升级和卸载验证
```

桌面版的价值是降低部署门槛，不是替代 Docker。Docker 继续作为服务器、开发和高级用户的标准部署方式。

## 8. 成功标准

本计划完成后，用户应该可以这样使用：

```text
打开 8787 → 拖入 CHARX → 看懂扫描摘要 → 点“RisuAI 完整翻译”
→ 等待任务完成 → 审核高风险项 → 导出并在 RisuAI 打开
```

最终目标不是把 CardLoom Translate 做成另一个简单字段编辑器，而是让它在保持深度解析、安全保护和审核能力的同时，具备接近轻量工具的第一分钟体验，并能通过 Windows 安装包直接交付给普通用户。
