# 代码结构

当前目录按运行边界和功能模块组织：

```text
config/                 配置默认值与环境变量校验
server/
  bootstrap/            可执行服务生命周期入口
  routes/               HTTP API 注册；每个文件都是一个端点路由组
  utils/uploads/        上传大小限制等无状态通用辅助逻辑
  application/          按 projects/scanning/translation/review/protocol/export 编排工作流
    export/             导出与模块命名空间审核
    projects/           项目创建与源文件保存
    protocol/           协议发现与持久化
    review/             审核元数据与审核事务
    scanning/           扫描结果重建与段落对账
    translation/        翻译任务创建与状态维护
  domain/               纯领域逻辑，按 card/lua/protocol/resources/translation 分组
  repositories/         文件存储与持久化访问
  scheduler.ts          模型调度、批次、重试和任务状态
src/
  app/                  应用状态、路由、hooks 与工作区壳
  components/           跨功能通用组件
  features/             按功能组织页面及其 components/utils/constants
  shared/               API 客户端和共享类型
tests/                  领域、应用和调度回归测试
docs/                   部署、边界和产品文档
```

约束：

- `server/index.ts` 只保留稳定启动导出；HTTP API 的实现入口是 `server/routes/api.ts`。
- 新的事务流程放在 `server/application/`，路由处理器只负责请求解析、调用服务和响应映射。
- 领域纯逻辑放在对应 `server/domain/<模块名>/`，避免跨模块复制保护规则。
- 前端页面放在 `src/features/<模块名>/`；页面中的独立面板、列表、弹窗和工具函数放入 `components/`、`utils/` 或 `constants.ts`。
- 原始卡片、草稿、审核候选和导出工件的状态边界不因目录迁移而改变。


## 任务生命周期与取消

- `server/routes/jobs.ts` 保留暂停、恢复、重试、取消接口和 HTTP 错误映射。
- `server/application/translation/job-lifecycle-service.ts` 在同一事务中更新任务、段落队列和项目；事务成功后才中断或启动调度。
- `job-runner.ts` 管理每个任务的执行实例；暂停后立即恢复会等旧执行退出，避免恢复请求丢失或重复运行。
- `postprocessing-store.ts` 在单次写入中同时检查项目版本、任务归属和任务状态，防止第二阶段覆盖新草稿或取消后的写回。
- 正文翻译、正则适配、名称翻译和分词共享任务取消信号；取消不记为模型失败。
- 页面报告的自动读取由 `automatic-loads.ts` 去重，失败后保留已尝试状态；用户可用页面刷新按钮重试，切换项目或明确失效时重新允许自动读取。

对应回归测试：`job-lifecycle-service.test.ts`、`job-runner.test.ts`、`runtime-alias-stage.test.ts`、`automatic-loads.test.ts`。

## 跨页面状态与编辑草稿

- `workflow-state.ts` 根据项目和任务共同推导引导状态；暂停、取消、失败以及阶段 2 不再沿用旧的“翻译中”提示。
- `useProjectWorkspace.ts` 负责项目轮询和请求版本检查。旧项目的操作结果不能覆盖当前项目，也不能打断首次分页加载；报告失败后由用户显式重试。
- 显式刷新项目列表和仪表盘时使用 `fresh=1` 绕过五秒缓存，确保导入、删除或修改后不会被缓存中的旧列表切回其他项目。后台轮询仍使用缓存。
- 审核文字与协议规则的刷新只更新未修改的本地输入；取消重译或批量操作失败时保留人工稿。
- 任务详情按当前选中的任务轮询；暂停、完成后的最终状态仍会更新，查看历史任务时保留选择。
- 正则编辑的保存结果、候选测试、导出基线校验分别展示。保存冲突只更新已保存基线，保留待保存的匹配式和替换输出；诊断刷新不决定保存是否成功。
- 单条正则在测试和保存期间锁定输入；已保存但仍有命中差异的规则继续显示疑点，导出保护规则保持有效。

对应回归测试：`workflow-consistency.test.ts`。浏览器验证使用临时端口和模拟卡片，不依赖真实模型或业务数据库。
