# 代码结构

当前目录按运行边界和功能模块组织：

```text
config/                 配置默认值与环境变量校验
server/
  bootstrap/            可执行服务生命周期入口
  routes/               HTTP API 注册；每个文件都是一个端点路由组
  utils/uploads/        上传大小限制等无状态通用辅助逻辑
  application/          按 projects/scanning/translation/review/protocol/export 编排工作流
    export/             导出与模块命名空间审核
    projects/           项目创建与源文件保存
    protocol/           协议发现与持久化
    review/             审核元数据与审核事务
    scanning/           扫描结果重建与段落对账
    translation/        翻译任务创建与状态维护
  domain/               纯领域逻辑，按 card/lua/protocol/resources/translation 分组
  repositories/         文件存储与持久化访问
  scheduler.ts          模型调度、批次、重试和任务状态
src/
  app/                  应用状态、路由、hooks 与工作区壳
  components/           跨功能通用组件
  features/             按功能组织页面及其 components/utils/constants
  shared/               API 客户端和共享类型
tests/                  领域、应用和调度回归测试
docs/                   部署、边界和产品文档
```

约束：

- `server/index.ts` 只保留稳定启动导出；HTTP API 的实现入口是 `server/routes/api.ts`。
- 新的事务流程放在 `server/application/`，路由处理器只负责请求解析、调用服务和响应映射。
- 领域纯逻辑放在对应 `server/domain/<模块名>/`，避免跨模块复制保护规则。
- 前端页面放在 `src/features/<模块名>/`；页面中的独立面板、列表、弹窗和工具函数放入 `components/`、`utils/` 或 `constants.ts`。
- 原始卡片、草稿、审核候选和导出工件的状态边界不因目录迁移而改变。
