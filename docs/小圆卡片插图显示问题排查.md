- 服务器：`ubuntu@1.117.66.171`，容器 `risuai`（RisuAI 2026.8.160）
- 卡片：`瓦普吉斯之夜：魔法少女小圆角色扮演`，`chaId 90fa237b-f687-4d7f-a244-5fc991efd3bf`
- 存档：`/opt/1panel/apps/risuai-local-sso/risuai/save/remotes/90fa237b-….local.bin`（1,984,083 字节）
- 排查方式：只读。拉取线上存档后，用**部署构建自带源码**（sourcemap `src/ts/parser/parser.svelte.ts`、`src/ts/process/scripts.ts`、`src/ts/cbs.ts`）
  在本地复刻 `editdisplay` 流水线，对卡片真实消息逐步回放。**未修改服务器上任何文件。**

## 一、结论（根因）

卡片里的立绘标签 `<img="名字">` 本身没问题，素材也在（2105 个 `additionalAssets`，文件都在 `save/` 里，AVIF 格式，magic 正确）。
问题出在**卡片自己的一条“对话换行”正则**上：它把立绘标签中间的引号当成了台词引号，往标签里面插了一个换行，
导致后面所有负责把标签变成图片的正则全部匹配失败，标签就原样以文字形式显示出来了。

具体是 `customscript[41]`（注释 `WALP 대사 줄바꿈: 닫는따옴표 후`）：

```
in : ([”"」])[ \t]*(?!(?:하고|…|的|说|说道|说着|地说|地|道|表示|称|认为|觉得|想|问|答|喊|叫|回答|心想|念|问道|答道|喊道)(?![가-힣]))(?![A-Za-z-]+=)(?=[“"「『]?[0-9A-Za-z가-힣ぁ-ヺ一-鿿*(])
                                  ^^^^^^^^ 注意这里是 *（原版是 +）
```

- `[”"」]` 会匹配 `<img="` 里的那个 `"`；
- `(?![A-Za-z-]+=)` 本意是“后面不是 `xxx=` 属性”，但标签里引号后面紧跟的是**名字**（`kyoko_normal_smug`），
  不是 `xxx=`，所以这条否定前瞻拦不住；
- 于是规则在标签内部插入了换行：

```
修复前： <img="kyoko_normal_smug">
被改写： <img="
         kyoko_normal_smug">
```

而所有这些“把标签变成图片”的规则都要求属性值在同一行、且有闭合引号（`"` 结尾）：

| 脚本 | 作用 | 改写后是否还匹配 |
| --- | --- | --- |
| `customscript[65]` | `WALP 에셋 디스플레이: 인물 감정 (SFW)`：`<img="((?:madoka\|sayaka\|…)_(?:normal\|mahou\|awakened)_[^"<>]+)\">"` | **否** |
| `customscript[64]` | NSFW 立绘显示 | **否** |
| `customscript[63]` | 69 横版 | **否** |
| `customscript[66]` | 魔女 / 使魔 / 麻美留 | **否** |
| `customscript[67]` | 开场卡 `walp_fmcard_*` | **否** |
| `customscript[61]` | `WALP 에셋 과거 숨김 (최근 5챗)`：`<img="(?!walp_fmcard_)[^"<>]+">` | **是（用 `[^"<>]+`，能跨换行）** |

于是出现两个后果，正好对应“插图显示不正常”：

1. **`customscript[61]` 先看到标签没问题，直接按“旧消息隐藏立绘”的规则把标签整段删掉** →
   最近 5 条以外的消息里插图位置**只剩空行**（“图没了”）；
2. 在**最新 5 条消息**（`customscript[61]` 放行）和**开场白**里，标签被保留，
   但显示脚本又不匹配，于是 `<img="…">` **以纯文本显示在正文中**（就是你截图里的样子）。

## 二、证据链

### 1. 线上消息里的标签是好的、素材是齐的

- 线上卡片聊天记录中共 44 个 `<img="…">`，其中 38 个名字能在 `additionalAssets` 里查到；
  查不到的 6 个是模型幻觉（`madoka_awakened_...`、`ASSET_NAME`、`character_action_detail`、`角色名_witch_default`）。
- 开场白 13 个标签，**全部**能找到素材。
- 例：`kyoko_normal_smug` → `assets/219f3a4c…8304.png`，服务器上文件存在（53,989 字节，AVIF）。
- 全局设置 `hideAllImages = false`，`th_nsfw = 1`，`th_asset_router_mode = 1`（main 模式），
  `toggle_TH_ASSET_OUTPUT` 未设置 → 按 `customscript`/`defaultVariables` 取到 `1`（开）。
  **所以不是“素材缺失 / 开关关掉 / 全局隐藏图片”造成的。**

### 2. 用部署构建自己的解析器回放

把线上存档里的真实消息喂进从 sourcemap 还原的 `risuChatParser` + `blockStartMatcher/blockEndMatcher` +
`processScriptFull`（含 `<cbs>`/`<order -100>` 的 flag 解析、`$&`/`{{data}}` 语义），逐步记录每个脚本前后的数据：

```
START len 54435 tags 13      ← 开场白，13 个标签
 51 WALP 대사 줄바꿈: 닫는따옴표 후     MATCH   ← 在这里把换行插进了标签内部
 62 WALP 에셋 줄바꿈                   （因此不再匹配）
 71 WALP 에셋 과거 숨김 (최근 5챗)       MATCH  tags 13 → 0   ← 旧消息里整段删除
 73/74/75/76/77 立绘显示脚本            全部 no match
END len 11412 tags 0
```

单独验证：把 `customscript[65]` 的输出模板做 `$1` 替换后交给真实解析器，
**能正常产出** `<table class="wpimg-asset-table">…<img class="wpimg-asset-img" src="{{raw::…}}">`。
也就是说显示脚本本身没坏，是输入被上游改坏了。

### 3. 新旧卡片对照（决定性证据）

同一段 `<img="kyoko_normal_smug">`，分别过**翻译前**（`tmp/remote-madoka-20260830-2018.fixed.json`）
与**线上**（`tmp/madoka-card-live.bin.json`）的这两条规则：

```
SNAPSHOT（翻译前）：标签保持 <img="kyoko_normal_smug">      显示脚本匹配? true
LIVE    （线上）  ：标签变成 <img="\nkyoko_normal_smug">    显示脚本匹配? false
```

两条规则的差异：

| 脚本 | 翻译前 | 线上 |
| --- | --- | --- |
| `customscript[41]` | `([”"」])[ \t]+(?!…)` | `([”"」])[ \t]*(?!…的\|说\|说道\|…)` |
| `customscript[42]` | `([.!?…。！？])[ \t]+([“"「])` | `([.!?…。！？])[ \t]*([“"「])` |

即：这次中文翻译除了给“引号后接中文”补了词表（`的/说/说道/…`）之外，还把两处
`[ \t]+` 改成了 `[ \t]*`。`+` 要求引号后**至少一个空白**（标签内部的 `"` 后面是字母，不匹配，安全）；
`*` 允许零个空白，于是标签内部那个 `"` 也被当成台词引号，规则就此泄进标签内部。

> 附注：工作台（card-translation-workbench）不会造成这个改动。
> `server/domain/card/card.ts` 的 `protectedPatterns()` 含 `/<\/?[^<>\n]{1,240}>/g` 和 `/\{\{[\s\S]*?\}\}/g`，
> 且 `isScriptPath()` / `isGenericProtectedPath()` 明确把 `customscript` / `regex` / `script` 路径排除在翻译范围外。
> 线上存档 `pluginStorage` 里 `card_cn_translator` 的 `character_backups` 为空，也没有留下可回溯的备份。

## 三、修复

在该卡片上用“规则编辑”把这两条正则改回 `[ \t]+`（保留新增的中文词表），或直接编辑卡片 JSON：

```jsonc
// customscript[41]  WALP 대사 줄바꿈: 닫는따옴표 후
// 把 ([”"」])[ \t]*   →   ([”"」])[ \t]+
"in": "([”\"」])[ \\t]+(?!(?:하고|하는|라고|라며|라는|이라고|이라는|라니|と|って|的|说|说道|说着|地说|地|道|表示|称|认为|觉得|想|问|答|喊|叫|回答|心想|念|问道|答道|喊道)(?![가-힣]))(?![A-Za-z-]+=)(?=[“\"「『]?[0-9A-Za-z가-힣ぁ-ヺ一-鿿*(])"

// customscript[42]  WALP 대사 줄바꿈: 여는따옴표 앞
// 把 ([.!?…。！？])[ \t]*   →   ([.!?…。！？])[ \t]+
"in": "([.!?…。！？])[ \\t]+([“\"「])"
```

修复后的行为（已用同一套复刻解析器验证）：

| | 当前线上 | 修复后 |
| --- | --- | --- |
| `<img="…">` 标签是否被插换行 | 是 | 否 |
| 立绘显示脚本是否触发 | 否 | **是** |
| 旧消息隐藏脚本是否仍生效 | 是 | 是 |
| 引号后接中文的断行 | 有 | 无（与卡片原始设计一致） |

代价说明：`[ \t]+` 下“句末引号紧跟中文”不会再断行（原本 `+` 时代就是这样）。
如果既想保留中文断行、又不想破坏标签，可用 `([”"」])[ \t]*(?!<(?:img|image)\b)(?!…词表…)`——
但这属于改卡片设计，建议先用上面的最小回退验证稳定后再考虑。

### 另外两个次要问题（与图片不显示无关，但会影响观感）

1. **模型会漏出占位符**：线上聊天里出现过 `<img="ASSET_NAME">`、`<img="character_action_detail">`、
   `<img="角色名_witch_default">`、`<img="madoka_awakened_...">`。这些名字不在素材表里，
   即使正则修好也不会显示（会被解析成空字符串），需要在 `prebuiltAssetCommand` / 提示词里再约束，
   或在脚本里对未知名字做兜底替换。
2. **`<Thoughts>…</Thoughts>` 会出现在正文里**：`parseThoughtsAndTools` 会把它折成
   `<details><summary>…</summary>`，截图里那段英文思考就是模型输出带出来的，属于模型侧问题。
