# 补丁管理与恢复

## 页面入口

- 补丁管理：选择 SSH 服务器或工作台可访问目录；按补丁读取文件、预检、安装。
- 安装记录与恢复：只展示当前目标的记录，核验文件或镜像后才允许恢复。
- 桥接与预设：独立的 RisuAI 网页插件和预设工具。
- 离线工具、补丁说明：下载脚本包、查询适用条件，不与在线安装表单混排。

## 状态含义

“已连接”仅代表目标可访问。“无需安装”表示当前文件已具备选定补丁的行为，不等于曾通过工作台安装，也不会凭空创建备份。

目录安装只修改文件，不自动证明运行实例已更新。源码修改后仍需重建并部署。Docker 安装会核对镜像 ID、容器健康状态和目标文件哈希；浏览器行为仍需单独核验。

修订号是脚本内容摘要，不是 RisuAI 的发布版本。脚本更新后只能重新预检，不能据此直接认定新版兼容。

## 文件恢复

安装器追加保存每次安装的标识、修订、时间、目标哈希和备份位置；卸载保留审计记录及备份。

恢复前检查：

1. 所有目标都属于指定根目录，不是符号链接。
2. 当前文件等于记录中的安装后哈希，备份等于安装前哈希。
3. 没有后续补丁修改同一文件，没有其他已记录的补丁依赖待卸载补丁。
4. 恢复确认仍有效，且没有其他补丁操作持有锁。

文件恢复中途发生可捕获的写入异常，会恢复本次操作已改动的文件。进程崩溃或断电后可能保留锁；此时需要管理员核对文件、备份和清单后处理，不能直接删除锁强行重试。

离线安装将 manifest.json 放在所选备份目录中。工作台目录代理沿用已配置备份目录上一级的 manifest.json；SSH 目录安装使用 /opt/cardloom-patch-backups/manifest.json。

```bash
node patches/risuai/patch-state.mjs status --root /path/to/RisuAI --manifest /path/to/manifest.json
node patches/risuai/patch-state.mjs remove --root /path/to/RisuAI --manifest /path/to/manifest.json --id RECORD_ID
```

## Docker 恢复

新的镜像安装在 /opt/cardloom-patch-backups/docker-* 保存记录、原镜像引用、Compose 文件校验值、覆盖配置和文件备份。维护脚本保留在服务器的备份目录内。

只允许回滚当前镜像对应的安装；更早的镜像安装必须逆序恢复。Compose 配置变化、原镜像丢失或容器应用层出现未记录修改时，自动恢复被禁止。回滚失败会尝试恢复当前补丁镜像；两次都失败会标记需要人工恢复。

```bash
bash /opt/cardloom-patch-backups/docker-history.sh history CONTAINER
bash /opt/cardloom-patch-backups/docker-history.sh remove CONTAINER RECORD_ID EXPECTED_IMAGE_SHA256
```

旧版手工安装或旧 Docker 备份不会被自动认定为可恢复记录。不可根据“无记录”判断“无补丁”。

## 验证边界

回归测试覆盖依赖、目标漂移、备份损坏、确认重放、并发操作、文件恢复异常和 Docker 命令模拟故障。浏览器测试在临时目录执行真实安装与卸载，并核对恢复字节。没有通过重建线上 RisuAI 容器来验证故障恢复。
