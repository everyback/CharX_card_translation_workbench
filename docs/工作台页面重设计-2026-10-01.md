# 工作台页面重设计

## 参考与取舍

本次参考了两个开源翻译管理项目的官方资料，并根据卡片翻译工作台的实际功能重新组织页面，没有引入它们的代码或组件依赖。

- [Weblate：翻译编辑器与 Zen Mode](https://docs.weblate.org/en/latest/user/translating.html#zen-mode)：在编辑时减少外围信息，让原文、译文与上下文服务于当前审核任务。
- [Tolgee：项目和翻译管理](https://docs.tolgee.io/platform)：区分项目管理、翻译内容、翻译流程、术语及集成等职责；项目是工作上下文。

采用专业工作台布局：持久侧栏管理项目，项目内使用 Tab 切换工作视图，项目工具常驻于 Tab 下方的分组按钮栏。审核需要原文、译文、定稿三栏，因此不增加常驻二层导航来挤占横向空间。既有深度链接继续可用。

## 页面结构

```text
工作空间
├─ 项目库：名称搜索、进度筛选、格式筛选、排序、导入
├─ 当前项目
│  ├─ 版本栏：切换版本、导入新版本
│  ├─ Tab：项目概览、翻译内容、翻译任务、对照审核、导出成品、版本记录
│  └─ 常驻分组工具栏：术语库、资源管理、脚本管理、协议规则、引用检查
└─ 全局工具：插件与补丁、关于工作台、模型设置
```

ST 预设继续使用独立转换界面，不出现普通卡片的审核、翻译、脚本和导出入口。

## 操作变化

1. 首次进入默认展示项目库。已有 `?project=...` 链接仍打开项目概览，带 `tab`、`segment` 的旧链接保留。
2. 概览负责推荐下一步、扫描摘要、风险提示和原始结构。翻译范围与语言设定可按需展开。
3. 翻译内容页集中保留扫描、范围选择和启动翻译。术语、资源、任务、脚本等页面不再重复显示完整引导和统计区。
4. 审核页保留原文、机器译文、人工定稿三栏。搜索和审核状态直接可用，其他筛选及批量操作默认折叠，并提示正在生效的高级筛选数量。
5. 新增导出成品页，集中展示已审核数、待审核或未翻译内容、任务状态、格式及语言方向。结构检查仍由原有保存/导出流程执行，页面不提前声称检查通过。
6. 删除当前版本收进项目操作菜单，继续使用原有确认流程；作为后续版本基础的版本需要保留。页头的导出按钮打开导出页。
7. 返回项目库后再进入同一项目，不再清空其未保存的审核定稿；项目级操作反馈不出现在项目库或其他独立页面。
8. 窄屏侧栏可展开/收起，选中页面后自动收起；项目卡片改为单列。

## 版本与增量翻译

- 现有项目自动视为 V1，保留原 ID、深度链接和已有内容。新版本需要在项目内明确导入，不按同名卡片自动合并。
- 一个项目拥有多个版本，每版保存独立原始卡片、模块、资源、草稿、任务和审核记录。导入时继承基础版本的语言、范围和术语配置。
- 项目库和左侧按项目聚合，展示最新导入版；切换到历史版仍可查看、审核和导出。版本记录显示基础版本及逐字段差异。
- 匹配依据是字段路径、片段类型、原文和协议分隔符。世界书等对象数组优先使用唯一稳定 ID，支持重排；没有 ID 时仅允许内容完整相同的对象移动；重复 ID 或重复片段不会猜测复用。
- 同字段原文未变且旧版有待审核/已通过译文时，检查当前保护规则后复制为本版待审核稿。不会继承旧版的人工豁免或直接导出。
- 原文改变、新增、匹配歧义、语言规则不一致或保护检查失败的字段不自动复用。改变字段的旧译文仍可对照。默认启动翻译只处理当前范围内未翻译/退回的字段。
- 复用记录保留来源版本、来源字段和当时的译文。重新扫描保留已存在的审核结果；手动清空或退回不会被普通重扫覆盖。
- 若新版已扫描、旧版之后才补完翻译，可在版本记录中点击“补用旧版译文”。只补入原文未变且没有译文或人工稿的未翻译字段；已有草稿、审核决定和刻意保留的空人工稿不会覆盖。当前版本存在排队、运行或暂停的翻译任务时禁止补用。补用及来源记录在同一事务内写入，重复操作不会重复修改。
- 重复 ID 在任一版本出现都视为匹配歧义，不将无法确认身份的旧字段误计为已移除。对象数组的身份计数和匿名对象哈希在单次比较内缓存，减少大型世界书的重复遍历。
- 切换到版本页时保留已打开工具的表单状态；版本页与工具容器使用不同组件标识，往返导航不会累积重复的版本区域。
- 创建版本及术语复制是一个事务；扫描、译文复用与来源记录是一个事务，失败会一起回滚。每次原始导入都单独保留，因此大型资源包会占用额外磁盘空间。

## 保护边界

翻译结果仍先进入草稿。只有审核通过的内容进入导出文件，其余保留原文。世界书原始触发词、变量及脚本保护规则不变；模型调度、持久化和后端导出逻辑复用既有服务。没有添加前端依赖或改变默认监听配置。

本次没有重启或替换 8787 服务，没有读取真实卡片数据库、API Key 或远程配置。新增界面样式集中在 `src/layouts/workbench/workbench.css`，导航元数据位于 `src/pages/workbench/model/navigation.ts`。

## 后续反馈：入口、读取和删除

- 术语库、资源管理、脚本管理、协议规则、引用检查改为常驻按钮，保留内容管理/高级工具分组，增加图标、边框和深色选中态。
- 初次读取段落最多并发 3 页，每页仍为 500 条，按页偏移合并；校验总数与页完整性，切换项目取消旧读取，取消额外 250ms 展示等待。术语与协议加载不再阻塞段落请求启动。
- 独立临时数据 3001 段卡片，三轮串行耗时 329/308/343ms，并发 212/206/246ms；中位数从 329ms 降到 212ms（约 36%）。仅衡量段落 HTTP 读取及解析，不代表实际卡片的整页渲染耗时。
- 左侧项目“…”提供删除整个项目，确认框列出全部版本数和不可撤销范围。服务端校验版本数未变化、所有版本无排队/运行/暂停任务；数据库删除和引用解除为单个事务。其他项目与工作台外文件不受影响。资源清理失败会明确反馈。
- 最终 npm test 498 项通过，npm run build 通过。浏览器验证常驻按钮切换、删除确认和取消；实际整项目删除、任务阻止、事务回滚、其他项目保留由隔离 HTTP 回归测试验证。
